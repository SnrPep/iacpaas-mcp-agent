# IACPaaS MCP-сервер и ИИ-агент

MCP-сервер-адаптер к графовой платформе IACPaaS и ИИ-агент, который работает с ним из **VS Code**, **Claude Code**,
**консоли** и **веб-чата**. Любая модель с вызовом инструментов (GigaChat, YandexGPT, Ollama, DeepSeek, OpenRouter,
GPT, Claude…). Контекст диалогов сохраняется между запусками.

> Сейчас проект работает с **реальной платформой** (`IACPAAS_BACKEND=http`, вход по логину/паролю) на ИР
> подгруппы — тема «Технологические газы»: «Загрузки/База технологических газов», её онтология и справочники
> (9 ИР, доступ «только чтение», список — `config/inforesources.json`). **Запись — только в свою папку
> «Загрузки/Песочница ИИ» и только с подтверждением** (подборки газов, пометки). Песочница
> (`IACPAAS_BACKEND=mock`, `fixtures/`) — для тестов и работы без сети.

## Что внутри

| Часть | Где | Что делает |
|---|---|---|
| MCP-сервер | `src/iacpaas_mcp/` | 14 инструментов чтения (в т. ч. `gas_query` – любой вопрос о газах базы одним запросом, проверка по онтологии, схема ИР и связей) + 7 изменяющих (только своя папка, с подтверждением), stdio и HTTP из одного кода |
| Агент | `src/iacpaas_agent/` | LangChain + LangGraph: реестр моделей, память в SQLite со сжатием кодом под бюджет модели, проверка ответа кодом (`verify/`), подтверждения, трасса, CLI, веб-чат |
| Настройки | `.env`, `config/` | ключи, режимы, лимиты; список ИР; профили моделей; инструкция агента |
| Клиенты | `.mcp.json`, `.vscode/`, `.github/agents/` | подключение в VS Code / Claude Code, custom agent |
| Тесты | `tests/` | 237 тестов: запрос к таблице газов по каждому типу вопроса, инструменты, HTTP-клиент, агент и проверка ответа, уточнения к прошлым вопросам, память и сжатие, веб и страница, транспорты, сбои и атаки |
| Документация | `docs/` | архитектура, инструменты, безопасность и сбои, сценарии, словарь, после доступа |

## Установка (один раз)

```powershell
cd iacpaas-mcp-agent
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[agent,models,dev]"
.venv\Scripts\python scripts\setup_clients.py      # .env, .mcp.json, .vscode/mcp.json для этой машины
.venv\Scripts\python -m pytest -q                   # проверка: все тесты зелёные
```
Нужен Python 3.11+. Для MCP Inspector — Node.js 22.19+. Linux/macOS: `.venv/bin/python`.

## Запуск

### 1. Claude Code (VS Code или терминал)
Откройте **папку проекта** в VS Code (или `cd` в неё и `claude`). Claude Code найдёт `.mcp.json` и спросит
разрешение на сервер `iacpaas` — разрешите. `/mcp` — статус. Дальше спрашивайте обычным текстом:
«Какие ИР есть?», «Какой состав у гелия марки 6.0?», «Проверь базу газов по онтологии».

### 2. VS Code (GitHub Copilot, режим Agent)
Откройте **папку проекта** (`iacpaas-mcp-agent`) как рабочую. Сервер `iacpaas` (stdio) VS Code берёт из `.mcp.json`
в корне проекта — доверьте папку и запустите его (`MCP: List Servers` → iacpaas → Start). В чате выберите режим Agent и агента
**IACPaaS Analyst** (`.github/agents/iacpaas.agent.md`, инструменты `iacpaas/*`). Один сервер и один агент:
читает ИР подгруппы и пишет только в «Загрузки/Песочница ИИ». Управление: `MCP: List Servers` → Start / Restart /
Show Output. Изменяющие инструменты — с предпросмотром нашего сервера: модель показывает его в чате и спрашивает «да / нет», выполняет только после вашего «да»; перед вызовом клиент сам спрашивает разрешение на инструмент (`IACPAAS_CONFIRM_MODE=chat` в `.mcp.json`). Окна сервера (MCP elicitation) здесь не используются: панель Claude Code в VS Code их не показывает и сама отвечает «отклонить».

### 3. Консоль
```powershell
.venv\Scripts\iacpaas-agent                         # модель AGENT_MODEL (auto), сервер стартует сам
.venv\Scripts\iacpaas-agent --model gigachat        # конкретная модель
.venv\Scripts\iacpaas-agent --model demo            # демо без LLM (сценарий) — проверить цепочку
.venv\Scripts\iacpaas-agent --session <id>          # конкретный диалог (без флага – последний диалог консоли)
.venv\Scripts\iacpaas-agent --new                   # новый диалог;  /help — команды, /compact — сжать
```

### 4. Веб-чат
```powershell
.venv\Scripts\iacpaas-web                           # http://127.0.0.1:8773 (WEB_PORT в .env)
```

### 5. Сервер отдельно (HTTP) — для нескольких клиентов
```powershell
.venv\Scripts\iacpaas-mcp --transport http          # 127.0.0.1:8765/mcp, нужен MCP_BEARER_TOKEN из .env
.venv\Scripts\iacpaas-agent --mcp http              # агент к нему
```
В VS Code это сервер `iacpaasHttp` из `.vscode/mcp.json` (спросит токен). Ответ `gas_query` по умолчанию
модель пересказывает дословно (`IACPAAS_PIECES=text` – для VS Code и любых клиентов); наш агент сам запускает сервер
с `IACPAAS_PIECES=marks` (метки `{{#id}}`, куски подставляет код). HTTP-сервер только для нашего агента –
`IACPAAS_PIECES=marks` в `.env`.

### Проверка без модели
```powershell
npx @modelcontextprotocol/inspector .venv\Scripts\python.exe -m iacpaas_mcp
.venv\Scripts\iacpaas-mcp --check                   # настройки: backend, вход, запись, путь лога
```

## Ключи: модели и доступ к IACPaaS
Значения пишутся только в `.env` и нигде не показываются.
```powershell
.venv\Scripts\iacpaas-keys                    # что задано, чего не хватает
.venv\Scripts\iacpaas-keys set gigachat       # ключ модели (ввод скрыт)
.venv\Scripts\iacpaas-keys set iacpaas        # доступ к платформе: логин/пароль или API-ключ
.venv\Scripts\iacpaas-keys use gigachat       # модель по умолчанию
.venv\Scripts\iacpaas-keys unset yandex       # стереть ключи профиля
```
То же в консольном агенте (`/keys`, `/key gigachat`). В веб-чате (кнопка «🔑 Ключи») — только ключи моделей:
доступ к платформе — настройка сервера, а не чата, он задаётся здесь, в консоли.
В VS Code / Claude Code модель выбирается в самом клиенте; доступ к IACPaaS сервер берёт из того же `.env`
(после изменения — `/mcp` → Reconnect или `MCP: List Servers` → Restart).

## Как получается ответ (версия 4)
- **Всё о газах базы считает и пишет код.** Модель выбирает запрос `gas_query` (операция и фильтры по схеме: какие
  газы, условия, «без», «кроме», самый / хуже / лучше, сортировка, сравнение, общие примеси групп, ошибки состава,
  смеси, расчёт), сервер считает по данным ИР и возвращает готовый кусок ответа и строку «понял вопрос так». Модель
  отвечает меткой куска; ответ по данным – только куски кода, текст модели вокруг них не показывается (свой текст
  модель пишет только там, где данных нет: общий вопрос, отказ, запись). Уточнение («а из них…», «вернёмся к …»)
  код относит к нужному прошлому вопросу и проверяет, что газы ответа – из него. Какие вопросы бывают и какой
  запрос на каждый – `docs/questions.md`.
- **Ответы о платформе тоже пишет код** (`src/iacpaas_mcp/pieces.py`): список ИР, вершины и дуги, метаданные,
  обзор, поиск, онтология, проверка по онтологии, схема набора ИР и дерево приходят готовым куском с меткой; модель
  их не переписывает.
- **Проверка – кодом** (`src/iacpaas_agent/check.py`): куски подставлены по меткам; кусок пришёл, а метки нет –
  ошибка; в тексте модели вне кусков нет газов базы и чисел (кроме номеров марок, чисел из вопросов и чисел из
  ответов инструментов без готового куска, например записи, – они сверены точно); вопрос о газах без запроса – ошибка; запрос сверяется с вопросом по явным признакам («без», «самый / хуже /
  лучше» – действие, по чему и среди каких газов, «общие», «во сколько раз», порог…). Ошибка – модель переписывает
  ответ (до двух раз); не помогло – показывается только то, что собрал код, текст модели – черновиком. Запрос не по
  вопросу – модели готовый исправленный запрос; не исправила – его выполняет код сам («код поправил запрос»).
- **Без кэша, данные всегда свежие:** каждый вопрос модель разбирает заново, каждый запрос читает ИР с платформы
  (`IACPAAS_CACHE_TTL=0`). История переписки – только контекст: к какому вопросу уточнение и о каких газах.
- **Уточнения** («а из них жидкие?», «сколько там связей?»): агент прикладывает к вопросу справку, собранную кодом, –
  прошлые вопросы и что по ним сделано (как понят запрос, какие газы, какой ИР и вершина); модель выбирает нужный
  вопрос (обычно последний) и делает новый запрос с явными газами – видно в строке «понял вопрос так».
- **Не о базе** (привет, «что такое ppm», код, рассказ) – отвечает модель, под ответом «написал ИИ, не из базы».
- На странице: кусок кода – на фоне с подписью «собрал код из базы · понял вопрос так: …»; под ответом – «собрал
  код» / «написал ИИ, не из базы», «код поправил запрос».
- Стенд на настоящей модели – `scripts\agent_bench.py --base tests\snapshot --model gigachat` (вопросы S, T, Q,
  диалоги D, D2; часть – `"Q*"`).
- **Память**: история хранится целиком, модели прошлое уходит сжатым кодом (без пересказа моделью): окно
  «Память диалога» (10–100 сообщений) и бюджет `context_tokens` профиля модели; что не влезло – выжимка: вопросы,
  числа и строки таблиц из ответов дословно. «Сжать весь чат» – `/compact`. Свой вопрос в веб-чате можно изменить –
  всё ниже удаляется, ход идёт заново.

## Модели
Профили — `config/models.toml`. `AGENT_MODEL=auto` берёт первую доступную. Новая модель = новая секция в
`models.toml`, код не меняется. Подробно: `docs/models.md`.

## Логи и данные
| Файл | Что |
|---|---|
| `logs/server.jsonl` | MCP-сервер: каждый вызов инструмента, ошибки, запросы к IACPaaS, `audit_write` |
| `logs/agent_trace.jsonl` | агент: какие инструменты вызвала модель, с какими аргументами, что получила |
| `logs/server.stderr.log` | поток stderr сервера, когда его запускает агент |

| `data/sessions.sqlite` | список сессий |
`logs/`, `data/`, `.env` в git не попадают.

## Запись данных (только своя папка)
Три настройки: `IACPAAS_ALLOW_WRITE` (появляются изменяющие инструменты; с `mock` — в песочнице),
`IACPAAS_REMOTE_WRITE` (разрешить реальную платформу) и `IACPAAS_WRITE_PATHS` (папки, куда можно писать; без них
на платформу запись не включается). Сейчас: `Загрузки/Песочница ИИ`. Каждое изменение — в два шага: предпросмотр
с токеном → подтверждение человеком (в веб-чате — кнопки «Разрешить / Отклонить» прямо с предпросмотром) → выполнение + `audit_write` в лог. Что агент пишет: подборки газов
(`save_selection`, новый ИР на той же онтологии, с пометками `notes`), черновики смесей (`save_mixture`), удаление своих ИР. Выданные ИР — только
чтение. Подробно: `docs/security.md`.
