# Архитектура

```
 Человек ──► VS Code (Copilot / Claude Code) ──MCP stdio──┐
 Человек ──► CLI / веб-чат (агент LangChain) ─MCP stdio | HTTP+Bearer─┤
                                                           ▼
                         MCP-сервер iacpaas (src/iacpaas_mcp)
                         ├─ транспорт: stdio | Streamable HTTP 127.0.0.1 (__main__.py)
                         ├─ инструменты: схемы, аннотации, ошибки, лимиты (server.py)
                         ├─ политика записи: выключатели + confirm_token (policy.py)
                         ├─ шлюз: кэш, повторы чтения, параллельность, сброс кэша (gateway.py)
                         ├─ граф: подсчёт, поиск, онтология, проверка JSON (graph.py, paths.py)
                         └─ бэкенд: HttpBackend → REST IACPaaS | MockBackend → fixtures/
```

## Ключевые решения
| Решение | Почему |
|---|---|
| Один объект сервера, два транспорта | требование «stdio и HTTP без дублирования»; stdio — для IDE, HTTP — для общего сервера |
| `.mcp.json` с абсолютным путём к `.venv` (генерирует `scripts/setup_clients.py`) — сервер `iacpaas` | один файл понимают Claude Code и VS Code (Copilot подхватывает его сам — в логе VS Code «workspace-dot-mcp»); на `iacpaas` ссылается custom agent (`iacpaas/*`). В `.vscode/mcp.json` — только HTTP-вариант: второй `iacpaas` там дал бы двойника (`mcp_iacpaas2_…`) |
| Бэкенд за интерфейсом + песочница | разработка и тесты без доступа к платформе; реальные экспорты кладутся в `fixtures/` |
| Подсчёт/поиск/онтология в адаптере | в REST API IACPaaS нет таких методов (они есть только в Java API агентов платформы) |
| Плоский список вершин с путями вместо вложенного JSON | модели проще читать и сразу передавать пути в следующие вызовы; меньше токенов |
| Необязательные аргументы `str = ""`, без `anyOf` | GigaChat не принимает Union-схемы; так схемы совместимы со всеми провайдерами (проверено тестом) |
| Подтверждение записи на сервере (HMAC-токен) + в клиенте | работает в любом клиенте; аннотации — лишь подсказки и не являются защитой |
| Агент: `create_agent` + middleware | трасса, перехват падений инструментов, повторы модели, лимиты, облегчённая история для модели, подтверждение человеком |
| История для модели: `ContextMiddleware` – сжатие кодом, а не резюме моделью | история в БД и в чате — целиком; модели прошлое уходит сжатым всегда в одном порядке: результаты инструментов старше предыдущего вопроса – заглушкой; окно «Память диалога» (10–100, по умолчанию 15, сдвиг рывками – реже ломается кэш GigaChat); бюджет `context_tokens` профиля модели (GigaChat-2-Max 24 тыс., Lite 12 тыс., локальная 3–4 тыс.); что не влезло – выжимка кодом: вопросы, числа и строки таблиц из ответов дословно, пути газов из вызовов; «сжать весь чат» (`/compact`) – отметка в списке сессий. Резюме моделью не годится: модель может пересказать неточно (требование – ничего не выдумывать); прежнее `SummarizationMiddleware` к тому же ломало кэш |
| Ответ о газах пишет код: `gas_query` (`query.py`) – план запроса по схеме, закрытый набор операций | вопросы «сыпались» на новых типах: проверка свободного текста угадывала регулярками, что спросили и к какому газу число; теперь модель выбирает запрос, код считает и пишет кусок и строку «понял так»; нет операции – «не умею», а не догадка (ТЗ: query_graph – «выполнить поддерживаемый запрос») |
| Ответы о платформе тоже пишет код: `pieces.py`, класс `Piece` и декоратор `pieced` в `server.py` | у каждого инструмента чтения – готовый кусок `answer` и метка `block` (список ИР, вершины и дуги, метаданные, обзор, поиск, онтология деревом, проверка, схема набора ИР, дерево подграфа); раньше модель переписывала схему сама и проверка сверяла только числа – перепутанные строки схемы прошли бы незамеченными |
| Как показать кусок – `IACPAAS_PIECES` | наш агент (веб-чат, консоль) подставляет кусок по метке `{{#id}}` – сервер он запускает сам с `marks`; Copilot и Claude Code меток не подставляют – по умолчанию `text`: подсказка «перескажи answer дословно», иначе человек увидел бы метку вместо ответа |
| Проверка ответа: `VerifyMiddleware` + `check.py` | ответ по данным – только куски кода (текст модели вокруг них не показывается и не вызывает повторов: раньше модель пересказывала в нём газы и числа, получала замечание и на повторе портила уже верный запрос); свой текст модели – где данных нет (общий вопрос, отказ, запись), и в нём ни газов, ни чисел базы; запрос ↔ вопрос по явным признакам; модель не исправила запрос – его выполняет код; не собрано – «ответ по базе не собран», а не догадка кода |
| Без кэша ответов и выгрузки; уточнения – справкой кодом (`follow_items` в `core.py`) | каждый вопрос модель разбирает заново, данные читаются с платформы при каждом запросе (`IACPAAS_CACHE_TTL=0`); на уточнение («а из них…», «сколько там…») модель получает список прошлых вопросов с тем, что по ним сделал код (понятый запрос, газы, ИР и вершина), – одинаковое уточнение к разным вопросам относится к своему вопросу |
| Уточнение относит к вопросу код: `check.follow_target`, `VerifyMiddleware._follow` | справку модель получала, но в длинной переписке не использовала («а какой из них хуже по водяным парам?» после кислородов искала по всей базе); теперь «из них» – к последнему вопросу, «вернёмся к аргонам без метана» – к вопросу с теми же словами; газы ответа не из газов того вопроса – запрос исправляется (`follow_fix`: отбор того вопроса + своё действие) |
| Правка вопроса: `RemoveMessage` в чекпоинте | как в основных чатах: вопрос и всё ниже удаляются из истории (и ожидающее подтверждение), ход – заново |
| Запись только по просьбе | `ConfirmButtonMiddleware`: изменяющий вызов без просьбы в сообщении пользователя («сохрани», «удали»… или «да» на предложение) не выполняется — `[not_requested]`; с просьбой — карточка «Разрешить / Отклонить» |
| Память — LangGraph `AsyncSqliteSaver` | диалоги и ожидающие подтверждения переживают перезапуск; один файл, без сервера БД; для многопользовательского режима — замена на Postgres |
| Модели — реестр `config/models.toml` | любая модель с tool calling подключается секцией; ключи — в `.env` |
| Сообщение во время работы: `/api/steer` + `SteerMiddleware` | как в Claude Code: получает тот же агент перед ближайшим шагом модели, коротко отвечает по ходу (текст рядом с вызовом инструмента) и продолжает задачу; не прочитано — можно забрать (`/api/unsteer`); ход закончился — уходит следующим вопросом |
| Знания из онтологии — на сервере (`knowledge.py`): карточка, таблица, проверка | слабая модель путает вложенные значения («не более» у суммы примесей, e-нотация); сервер отдаёт готовый текст и числа, модель только пересказывает |
| Пометки — комментарии в подборке при импорте (`save_selection(notes)`) | `PUT /api/data/update` на платформе отвечает «ошибка» без пояснения (18.10.2026), импорт работает |
| Очередь к модели: `parallel` в `models.toml` + `ModelGate` | GigaChat Freemium принимает один запрос за раз (второй — 429); параллельные ходы ждут очереди, пока другой ждёт платформу. Между процессами (консоль и веб-чат на одном ключе) — файловая блокировка `data/model-<группа>.lock` (`locks.py`) на один шаг модели, с честной очередью (файл `.wait`); ждать дольше 150 с — ответ «модель занята другим окном»; 429 не повторяется, а сразу объясняется |

## Клиенты: кто решает, кто исполняет
Модель только пишет текст: «вызови такой-то инструмент с такими аргументами» и итоговый ответ. Вызывает инструмент,
возвращает модели результат и крутит цикл «модель → инструмент → модель», пока она не ответит, — программа-хост.
В VS Code хост — Copilot или Claude Code, в standalone-режиме — наш код на LangChain.

| | Copilot (VS Code) | Claude Code (VS Code) | Веб-чат | Консоль |
|---|---|---|---|---|
| Кто решает, что вызвать и что ответить | модель GPT (Auto → GPT-6 Luna) | модель Claude | модель GigaChat | модель GigaChat (или другая из `config/models.toml`) |
| Кто исполняет вызовы и ведёт цикл | Copilot | Claude Code | **наш код** (LangChain) | **тот же наш код** |
| Инструкция агента | **`.github/agents/iacpaas.agent.md`** | подсказка самого MCP-сервера | **`config/agent_prompt.md`** | **тот же `config/agent_prompt.md`** |
| Где настроен сервер | `.mcp.json` | `.mcp.json` | запускается сам, дочерним процессом | так же |
| Запуск | панель чата VS Code | панель Claude Code | `iacpaas-web` → браузер | `iacpaas-agent` в терминале |
| Разрешения | спрашивает про вызов и про результат инструмента | спрашивает про вызов инструмента | изменения — только с подтверждением | так же, ответ «да/нет» в терминале |
| Память и трасса | история чата Copilot | история сессий Claude Code | **наша**: SQLite, `logs/agent_trace.jsonl` | **та же** (диалог продолжается: `--session <id>`) |
| **MCP-сервер и данные** | **наш `iacpaas`** | **наш `iacpaas`** | **наш `iacpaas`** | **наш `iacpaas`** |

Веб-чат и консоль — один и тот же наш агент с двумя интерфейсами (ТЗ, п. 8: «CLI или небольшой HTTP/UI
интерфейс»). Copilot спрашивает и про результат инструмента, потому что инструменты чтения помечены
`openWorldHint: true` (данные из внешней системы) — защита клиента от подсказок, спрятанных в данных.
Один сервер и один агент во всех клиентах: читает выданные ИР, пишет только в `Загрузки/Песочница ИИ`
(`IACPAAS_WRITE_PATHS`; проверка папки — на сервере до предпросмотра).

## Протокол
SDK `mcp` 2.x поддерживает обе эпохи протокола: 2026-07-28 (без состояния, `server/discover`) и 2025-11-25
(`initialize`). Версия согласуется автоматически; в тестах stdio-соединение договаривается на 2026-07-28.

## Версии (проверено)
Python 3.12 · mcp 2.3.0 · fastmcp 4.0.11 · langchain 1.4.3 · langgraph 1.2.14 · langgraph-checkpoint-sqlite 3.1.1.
`langchain-mcp-adapters` не используется: архивирован и требует `mcp<2`; вместо него `langchain.mcp.MCPAdapter` (beta).
