# Безопасность и устойчивость

## Модель угроз (что защищаем и от чего)

| Актив | Угроза | Защита | Проверено тестом |
|---|---|---|---|
| Данные на платформе | случайное или навязанное (prompt injection) изменение | запись — только в папки `IACPAAS_WRITE_PATHS` (проверка до предпросмотра, `[read_only]`); без флагов и папок инструменты записи не регистрируются; клиент HTTP отказывает **до** отправки запроса; двухшаговое подтверждение HMAC-токеном; подтверждение человеком в клиенте | `test_writes_disabled_send_nothing`, `test_server_over_http_backend_has_no_write_tools_even_if_allow_write`, `test_read_only_by_default_no_write_tools` |
| Подтверждение записи | модель «подтверждает сама себя» или меняет аргументы после предпросмотра | **веб-чат и консоль:** предпросмотр сразу уходит человеку карточкой «Разрешить / Отклонить», токен подставляет агент, модель его не видит; без просьбы в сообщении запись не начинается. **VS Code / Claude Code / Copilot** (`IACPAAS_CONFIRM_MODE=chat`): модель показывает предпросмотр в чате и спрашивает «да / нет», клиент спрашивает разрешение на вызов инструмента; токен видит модель, поэтому здесь защита — разрешение клиента и policy gate (только «Песочница ИИ», два шага, токен одноразовый и привязан к аргументам). Окна сервера (MCP elicitation) работают, если `IACPAAS_CONFIRM_MODE` не задан, но панель Claude Code в VS Code их не показывает и сама отвечает «отклонить» (проверено 18.10.2026); строгий режим `IACPAAS_REQUIRE_DIALOG=true` — запись только через такое окно. Токен = HMAC(операция, аргументы, время, случайная часть) с секретом процесса; одноразовый; живёт 5 мин; иные аргументы → отказ | `test_policy_token_bound_single_use_and_expiry`, `test_write_two_step_in_sandbox`, `test_confirm_dialog_in_client_with_elicitation`, `test_write_without_request_is_refused` |
| Ключ IACPaaS | утечка в модель, логи, git | ключ знает только сервер; модель видит лишь результаты; маскирование `***` в логах и трассе; `.env` в `.gitignore`; токен клиента не пересылается на платформу (нет token passthrough) | `tests/test_paths_graph_policy.py` (redact), ревью |
| MCP-сервер по HTTP | посторонний клиент, DNS-rebinding | только `127.0.0.1`; Bearer-токен ≥ 16 символов, сравнение за постоянное время; без токена сервер не стартует; SDK проверяет Host/Origin для localhost | `test_http_requires_bearer_token`, `test_http_refuses_to_start_without_token` |
| Веб-чат | чужой сайт в браузере шлёт запросы (CSRF), DNS-rebinding, мусорные запросы | только `127.0.0.1`; проверка Host (421) и Origin (403); `WEB_TOKEN` по желанию; лимит тела 1 МБ (413); ошибки без трейсбеков | `test_web_rejects_foreign_host_and_bad_input`, `test_web_chat_approval_and_guards` |
| Ключи моделей | попадание в подпроцесс сервера, в git | подпроцесс получает только нужные переменные (`IACPAAS_*`, `MCP_*`, `LOG_*`, системные); ключи — только в `.env` | ревью `CHILD_ENV_*` в `core.py` |
| Файловая система | запись вне проекта | сохранение экспорта — только внутрь `fixtures/` | `test_check_platform_refuses_path_outside_fixtures` |
| Достоверность ответа | модель выдумала число, взяла число другого компонента или газа, газа нет в базе, пропустила марку | всё из данных пишет код готовыми кусками – о газах `gas_query` (`query.py`), о платформе `pieces.py`; модель отвечает меткой, ответ по данным – только куски кода (текст модели вокруг них не показывается). Проверка кодом (`check.py`): метки – только из результатов, кусок есть – метка обязательна, в своём тексте модели (где данных нет) – ни газов, ни чисел базы, запрос сверяется с вопросом, уточнение – с газами своего прошлого вопроса; не так – модель переписывает (до 2 раз), запрос исправляет код, иначе показывается только собранное кодом или «ответ по базе не собран» | `tests/test_check.py`, `tests/test_query.py`, `tests/test_server_tools.py` |
| Ресурсы машины | огромные ответы, зацикливание агента | лимиты depth/вершин/символов; импорт ≤ 2 млн символов; лимиты вызовов инструментов и модели на вопрос; тот же вызов в одном ответе не повторяется; модели — история без старых результатов инструментов и окно памяти | `test_subgraph_depth_and_truncation`, `test_oversized_json_rejected`, `test_limits_stop_runaway_agent` |

### Prompt injection
Метки и комментарии вершин — данные из внешней системы, в них может оказаться текст вида «игнорируй инструкции».
Модель может этому поддаться — полностью исключить это нельзя. Поэтому всё опасное защищено **вне модели**:
запись выключена; если включена — нужен токен с сервера и явное «да» человека в клиенте. Чтение безопасно по природе.

## Что происходит при сбоях

| Сбой | Поведение | Проверено |
|---|---|---|
| Платформа не ответила (таймаут > 60 с) | чтение повторяется 2 раза (1 с, 2 с), затем модель получает `[timeout] … можно повторить позже` | `test_platform_timeout_is_retried_then_reported` |
| Платформа «на обслуживании» (`platformUnavailable`, 502–504) | повтор, при восстановлении — обычный ответ | `test_platform_unavailable_flag_and_recovery` |
| Неверный ключ / пароль (401/403) | без повторов; `[auth] … сообщите пользователю` | `test_auth_error_not_retried_and_explained` |
| JWT истёк | один автоматический повторный вход и повтор запроса | `test_signin_and_relogin_on_expired_jwt` |
| Ответ не JSON | `[platform_error] Ответ платформы — не JSON` | `test_garbage_response_is_reported` |
| Нет такого ИР / вершины | `[not_found]` + «Похожие ИР: …» / список потомков | `test_errors_are_diagnosable_for_the_model` |
| Неверные аргументы (depth > лимита и т. п.) | отклоняется схемой до вызова, модель видит причину | там же |
| Запись: аргументы не совпали / токен просрочен / повторно | `[confirmation] …`, данные не меняются | `test_write_two_step_in_sandbox` |
| Упал MCP-сервер / обрыв связи во время вызова | вызов превращается в `[tool_unavailable]` для модели, история диалога остаётся корректной, следующий вопрос работает | `test_tool_crash_keeps_dialog_consistent` |
| Сбой провайдера модели (сеть, 5xx) | 2 повтора; затем ответ с ошибкой, сессия продолжает работать | `test_model_failure_does_not_break_session` |
| Модель занята другим окном (консоль и веб-чат на одном ключе GigaChat) / 429 | общая очередь между процессами (файловая блокировка), в окне — «модель занята другим окном – жду очереди»; дольше 150 с — понятный ответ; 429 без повторов — понятный ответ | `test_two_windows_share_one_model`, `test_gate_busy_and_429_give_clear_answer` |
| Нет ключа для выбранной модели | понятное сообщение «задайте в .env …», без падения | `test_missing_model_key_is_reported` |
| Агент зациклился | лимит вызовов инструментов и модели на вопрос | `test_limits_stop_runaway_agent` |
| Перезапуск во время ожидания подтверждения | ожидание сохранено в SQLite, продолжается после запуска | `test_write_requires_human_and_survives_restart` |
| Два запроса в одну сессию одновременно | выполняются по очереди (блокировка на сессию) | `test_concurrent_requests_same_session` |
| Пользователь закрыл ввод при подтверждении (CLI) | считается отказом | ревью `cli.py` |
| Личный `.env` при тестах | при явном `IACPAAS_ENV_FILE` читается только он | `test_explicit_env_file_is_exclusive` |

## Чего проект намеренно не делает
- Не публикует сервер в сеть: для этого нужен TLS и настоящий OAuth 2.1 (`TokenVerifier` — точка подключения).
- Не хранит пароли платформы в коде: только `.env`.
- Не пишет в выданные ИР: запись на платформу — только в свою папку «Загрузки/Песочница ИИ» (решение пользователя,
  14.10.2026), каждое изменение — с подтверждением человека.
- Не запускает сервисы платформы на реальной платформе: их действие папкой не ограничить.
